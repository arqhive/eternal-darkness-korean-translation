# 이터널 다크니스 (GC, GEDJ01 기반) 한글화 분석

작성 2026-10-01 · 1단계 · 번역 원문은 북미판 영어, 높임은 일본어판 대응 줄 참고

## 판정: 가능 (돌핀 재확인 조건)

구조는 모두 풀렸고, 넣고 빼는 도구도 다시 만들어 검증했습니다.
큰 난관이던 압축(`*SK_ASC*`, 인코더 없음)은 무압축 우회 패치로 해결합니다. 이번에 새로 짠 패치는 에뮬레이터 검증까지 끝났고, 돌핀 확인은 2단계에서 다시 합니다.
남은 부담은 분량(영어 약 17.7만 자)과 폰트 칸 수입니다.

## 텍스트 형식

| 층 | 형식 |
|---|---|
| 파일 압축 | `*SK_ASC*` 적응형 산술부호(해제 루틴 0x8013fc58, 래퍼 0x8014191c). 일본판 284개 / 북미판 280개 |
| 묶음 | `[개수][0x6B5][(오프셋,크기)×개수]` 재귀 구조 |
| 문자열표 | `[항목 수][0xFB90][(오프셋,길이)×항목 수]`, 오프셋은 표 기준, 길이 0 = 빈 항목 |
| 레코드 | 4바이트 머리 + Gage BPE(바이트 쌍 압축) 블록 |
| 본문 | 0x18바이트 헤더 + `c\0` + [라벨 32+64바이트] + 텍스트 + `00 00` |
| 글자 | 북미판 1바이트 ASCII / 일본판 2바이트 글리프 번호(상위 바이트=폰트 장, 하위=칸) |
| 제어 | `\ay`·`\aw`(색), `~p` 등(태그 목록 정리는 4단계) |

## 일본어 글자표(높임 참고용)

- 일본판 텍스트는 글리프 번호라서 그대로는 읽을 수 없습니다. 실행 파일에 Shift-JIS 대응표가 없습니다.
- 가나·영숫자는 폰트 배열 순서로 복원할 수 있고, 높임 판정(です·ます·だ 등)은 대부분 가나로 됩니다.
- 한자 약 1,200자는 폰트 그림을 글꼴과 대조해 대응표를 만듭니다(4단계).

## 위험 요소

- **분량**: 영어 약 17.7만 자. 9/27에 같은 이유로 한 번 취소한 적 있음.
- **폰트 칸**: 한글 글자 수가 1,536칸을 넘으면 장 추가가 필요하고, 동작은 아직 확인하지 않음.
- **시스템·책 묶음 대응**: 북미판에는 라벨이 없어서 순번 대응을 검증해야 함. 일본판 사본 4벌·3벌의 차이도 확인해야 함.
- **우회 패치 자리**: 디버거 전용 함수 자리를 덮어씀. 9/27 판은 돌핀에서 동작했지만 이번 판은 새로 짠 것이라 다시 확인해야 함.
- **용량 여유 21MB**: 그림을 바꿔도 크기는 같지만, 컷신 파일이 더 커지면 줄어듦.
